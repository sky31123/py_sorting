| Bubble Sort    | n             | n<sup>2</sup>       | n<sup>2</sup> | 1          | 1             | 1           | Yes       | <ul><li>Only for educational Purpose</li><li>Compare adjacent elements only</li><li>n-i-1 because with each iteration of outer loop largest element goes to right</li></ul>                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Comb Sort      | n             | nlog<sub>1.3</sub>n | n<sup>2</sup> | 1          | 1             | 1           | No        | <ul><li>Best Case: Array is already sorted, so no swaps required and log<sub>1.3</sub> is considered small constant so O(n).</li><li>Average Case: Here log<sub>1.3</sub> is not considered constant so O(nlog<sub>1.3</sub>n).</li><li>Worst Case: Here algoritham continues to swap after gap is one (essentially bubble sort), so O(n<sup>2</sup>)</li><li>Sorting algos with O(n) best case linear time complexity and O(1) space complexity with no recursion allowed are insertion sort and comb sort, comb sort has better average time complexity but insertion sort is stable.</li></ul>                                                      |
| Selection Sort | n<sup>2</sup> | n<sup>2</sup>       | n<sup>2</sup> | 1          | 1             | 1           | No        | <ul><li>Although seems stable selection sort is not stable, because when i is swapped with min, i could move after same value in the array.</li><li>Gurantees at most n-1 swaps, lowest of all so use when memory writes are too expensive.</li></ul>                                                                                                                                                                                                                                                                                                                                                                                                  |
| Insertion Sort | n             | n<sup>2</sup>       | n<sup>2</sup> | 1          | 1             | 1           | Yes       | <ul><li>SHIFTs are cache friendly and faster/cheaper than SWAPs hence insertion sort is better choice over Bubble sort which has same best/avg/worst time complexity</li><li>Insertion sort is good choice when stabiity is required and data is nearly sorted.</li></ul>                                                                                                                                                                                                                                                                                                                                                                              |
| Quick Sort     | nLogn         | nLogn               | n<sup>2</sup> | logn       | logn          | n           | Yes       | <ul><li>Time Complexity is nLogn, because with every logn split you iterate through array n. Intuitively with every split you get smaller array to sort so not n<sup>2</sup></li><li>Worst time complexity occurs when you end up selecting pivot that's either smallest or largest resulting essentially in one split (in already sorted array picking up first or last element everytime), ending up in n<sup>2</sup> comparisons.</li><li>Use when you need Stable, In place and best average case sorting algo.</li><li>It's one of the practical sorting algorithm due to stability, nLogn time complexity and excellent cache locality</li></ul> |
| Merge Sort     | nLogn         | nLogn               | nLogn         | n          | n             | n           | Yes       | <ul><li>use when you need stable and consistent performance sorting algorithm and memory is not constraint</li><li>Merge and Quick sort can benefit from parallelism.</li></ul>                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Heap Sort      | nLogn         | nLogn               | nLogn         | 1          | 1             | 1           | No        | <ul><li>use when stability is not required but consistent nLogn time complexity is required with constant space complexity.</li><li>if you build heap one element at a time it's nLogn but with bottom up approach with array already defined it's O(n), SUM(n/2<sup>h</sup>*h) = n, The expensive nodes (near the top) are very few.The cheap nodes (near the bottom) are many.</li><li>you actually use max heap and then extract them one by one putting them at last while also reducing the heap length to get final sorted array.</li></ul>                                                                                                      |
